# 别让 AI 一上来就无脑烧满算力：WEConverge，让长任务真正收敛

大家用 AI 写代码时，肯定都遇到过这些让人血压升高的场景：

- 杀鸡用牛刀：明明改两行代码的小需求，AI 一上来就开满思考模式（Thinking Max），硬憋几分钟，白白浪费额度和时间；
- 卡住就鬼打墙：一旦报错或思路不对，它就在同一条死胡同里反复试错，输出一堆看似努力实则没用的垃圾改动；
- 盲目开分身：动不动就并发拉起四五个子 Agent，看似热闹，其实都在原地打转，彼此抄答案，纯纯浪费 token；
- 额度见底才发现跑偏：钱花光了、时间耗尽了，最后来一句“对不起我没搞定”。

WEConverge 就是为了解决这些痛点而做的。

它不是另一个新模型，也不是推倒重来的新框架，而是直接跑在 Oh My Pi（OMP）之上的 AI 原生调度插件。

一句话概括它的核心逻辑：
> 把“用多少算力、派什么角色”的决定权交给执行过程中的真实证据——能低成本搞定的绝不多花一分钱；真正卡住了，按梯队精准升级，及时止损。

================================================================================
1. 默认克制：绝不在任务开始前瞎猜难度
================================================================================

传统的调度方式很别扭：任务还没开始，就非要你选“这次开 Medium、High 还是 Max？要不要开多 Agent？”。但事实是：在没动手之前，谁也不知道这道题到底有多难。

WEConverge 不搞事前的“拍脑袋分类”，也不额外多跑一轮模型去评估难度。

它始终坚持低成本起步：
- 默认就用当前主力模型；
- 默认保持 Medium 思考强度；
- 默认单 Agent 独立干活。

简单问题三两下搞定，零额外开销；只有当代码真实报错、验证失败、确认原有路径走不通时，系统才允许 AI 申请更多资源。

================================================================================
2. 证据驱动：卡住了换思路，而不是换个姿势继续死磕
================================================================================

很多时候 AI 任务失败，不是因为“想得不够多”，而是“方向一开始就错了”。

WEConverge 逼着 AI 在遇到非简单任务时，先在内部拿出几个本质不同的解题方向（比如不同的根因假设、不同的验证路径、不同的修改模块），选定最优解再动手。

一旦当前方案走不通，AI 不能原地打转，必须提交明确的决策：
- 是切换备用方案？
- 是派一个低成本探路 Agent 去摸清未知事实？
- 是引入专门的代码审查/架构角色？
- 还是事实缺失（SOURCE GAP），需要停下来向用户要信息？

每一次算力升级，都必须说清楚“我缺少什么证据、新动作能带来什么新信息”。绝不搞没有信息增量的盲目并发。

================================================================================
3. 守住钱包：严禁后台私自开 Max
================================================================================

WEConverge 内置了清晰的成本阶梯：Medium -> High -> XHigh 逐级递增，自动调度最高到 XHigh。

但有一条铁律被写死了：任何自动动作若解析到 Max 会在执行前直接拒绝，绝不会在后台偷偷把额度烧穿；用户通过 OMP 自行选择的模型/思考强度属于自动调度之外，不由该护栏拦截。

它不搞虚头巴脑的“AI 预估 token”，也不搞昂贵无用的“周期性自我反思”，每一分额度都花在刀刃上。

================================================================================
4. 无缝复用 OMP：即插即用，绝不搞全家桶绑架
================================================================================

WEConverge 不去重新造一套 Lead、Task、Scout 等角色。它直接借力 OMP 原生强大的模型路由、任务派遣、工具调用和会话管理能力。

它只做自己最擅长的事：当好裁判和调度员，判断什么时候值得调用这些能力。

作为一个独立的用户级 Extension，它不侵入 OMP 核心代码，安装卸载零负担。

================================================================================
5. 真实记录：AI 说了什么不重要，跑了什么才算数
================================================================================

很多调度工具最怕“死无对证”——AI 嘴上说“我已经派了专家模型去优化”，实际上底层根本没调通或者降级了。

WEConverge 实行请求与实跑分离：
- AI 请求了什么角色、什么模型；
- 系统底层真正匹配到了哪个模型、什么 effort；
- 派出的子任务跑了多久、产出了什么补丁；
- 当前任务处于什么阶段、有没有恢复初始状态。

所有动作全链路审计落盘。如果缺少底层遥测数据，它就老老实实标记为 SOURCE GAP，绝不拿 AI 的漂亮话糊弄你。

================================================================================
6. 实测表现：相同任务配对对比，速度实打实提升
================================================================================

在相同任务、相同 prompt、相同 commit、相同主模型的 5 组严格控制变量配对测试中（涵盖 pytest、Matplotlib、Django、Seaborn、Astropy 等开源真实问题）：

- 胜负对比：WEConverge ON 取得 3 胜 1 负 1 平；
- 耗时表现：ON 平均耗时 9.81 分钟，OFF 平均耗时 11.23 分钟，总体提速约 12.6%；
- 局部亮点：在 Seaborn 任务中提速 43%，在 Matplotlib 任务中提速 26%；
- 可靠性：ON/OFF 均保持 5/5 正常完成交付，提速没有牺牲代码质量。

我们不吹嘘“百分之百全面碾压”，在部分超长任务上它依然需要继续打磨。但数据证明了一个事实：一套清醒、克制的收敛策略，确实能帮主力模型少走大量弯路。

================================================================================
7. 极简操作：两条命令搞定一切
================================================================================

日常使用没有任何心智负担，直接在 OMP 里输入：

  /weconverge on       # 开启智能调度
  /weconverge off      # 关闭智能调度
  /weconverge status   # 查看当前状态与 baseline
  /weconverge reset    # 重置当前任务状态

开启后，后续的新任务自动享受策略加速；不想用了随时一行命令关掉，完全还原原有使用习惯。

================================================================================
总结
================================================================================

如果你用 AI 只是写写几十行的打卡脚本，你可能不需要它。

但如果你经常把复杂的大任务、长链路 Debug、跨文件重构交给 AI，受够了无脑死磕、算力失控、子 Agent 乱跑——

那么你需要的往往不是更贵的模型，而是 WEConverge 这套懂克制、讲证据的调度策略。

少走冤枉路，算力花在刀刃上，让每一次长任务稳稳收敛。
